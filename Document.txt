Problem statement : (based on my understanding)

        They said design and implement the distributed multiple robot collaborative slam , it means we need to perform 
slam or mapping with more than one robot , and each of the robot makes a local map , and we create a node to fuse the 
local maps of the robots and generate the final global map. This node is one of the main thing in this task , so it 
have an lot of things to consider like unknown initial poses , overlapping trajectories , map inconsistencies and drift.
And we need to create that pipeline in decentralized architecture, it means each feautre we create the separate nodes 
by make the calls through we use that feautre.

Deliverables:

        An autonomous map-merging pipeline and a real time visualization showing the individual robot maps , poses and 
a mergered global map.
        We need to detect and resolve the overlaps , estimates transforms and map conflicts.
        We need to create this thing to support the a new robot is joining or leaving without map cracks.

Assumption :

        Turtle bot 3 robot is used in this task.
        Hospital based world is used in the task.

System Architecture :

        Robot 1 → SLAM → /burger/map ┐
                                      ├ → Map Merger → /map
        Robot 2 → SLAM → /waffle/map ┘  


Approach :

        1. visualise robot in rviz , world in gazebo. 
        2. spawn a single robot on the hospital world.
        3. spawn the multiple robots in that world.
        4. implement the collaborative slam.
        5. create the map merging pipeline or map fusion node.
        6. resolve the mentioned problems while merging happens.
        7. implement the adaption in code for a robot is suddenly joined or removed from the environment.
